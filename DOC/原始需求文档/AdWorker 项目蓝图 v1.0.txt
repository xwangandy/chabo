下面这份我按“可执行的项目蓝图”来写，不按空泛愿景写。

先说明一个现实判断：你要的是“尽可能一次把方向定准”，这个可以做到 80%–90% 准确，但不可能真的一次性把所有细节永久定死。因为这种双边平台的很多关键参数，必须在真实交易里校准，比如频道准入门槛、广告密度、结算周期、低质广告拦截阈值、退款规则、作弊判定线。这些不可能完全靠脑内设计定终局。真正正确的做法，不是追求“永不修改”，而是把“大框架、边界、核心账本、核心流程”一次定稳，把“可调参数”留成配置层。这个才是成熟方案。Telegram 官方已经有自己的广告平台，面向公开单向频道投放 sponsored messages；官方广告基于频道上下文而不是用户个人信息，并明确存在创作者分成机制。与此同时，市场上也已经存在第三方 Telegram 广告撮合平台和通过 bot/API 连接频道的做法，这说明“广告主—频道主—平台”的交易模型本身是成立的，只是你要做的是更适合中文 Telegram 生态、且更强调可控与可信的一版。([Telegram广告平台][1])

# AdWorker 项目蓝图 v1.0

## Telegram 广告撮合与投放平台

## 1. 项目定义

AdWorker 不是“发广告机器人”，而是一个面向 Telegram 生态的广告交易与履约平台。

它连接两端：

一端是广告主。
广告主要的是可控投放、可信曝光、可追踪效果、低沟通成本。

另一端是频道主。
频道主要的是低打扰变现、透明收益、可控广告频率、可选广告类型、稳定结算。

平台本身提供六类核心能力：

1. 广告审核
2. 频道接入与评级
3. 广告与频道匹配
4. 自动投放执行
5. 数据计量与结算
6. 风控与争议处理

项目目标不是“让所有人都喜欢”，而是让交易双方都觉得：
“比线下私聊谈单更省事、更透明、更稳定。”

这个目标切实际，而且可以做成产品护城河。

---

## 2. 项目边界

### 2.1 本项目做什么

AdWorker 负责：

* 广告主开户注册、充值、下单
* 广告素材提交、审核、排期
* 频道主接入、频道配置、广告偏好设置
* 平台自动匹配可投频道
* 机器人按规则发广告到频道
* 平台记录投放结果与基础效果数据
* 平台为频道主生成收益
* 平台为广告主扣费与出报表
* 平台处理异常、申诉、退款、冻结

### 2.2 本项目不做什么

AdWorker 不负责：

* 重型视频转码、水印渲染、媒体重建引擎
* 内容采集和频道拷贝引擎
* 群管和内容审核全家桶
* 增长刷量类能力作为正式产品能力
* 一开始就做开放 API 平台和复杂实时竞价系统

也就是说，它是“广告交易与履约平台”，不是“Telegram 万能后台”。

---

## 3. 为什么这个项目有成立空间

Telegram 官方广告系统主要是 sponsored messages，定位是公开频道广告投放，广告形式和平台规则由 Telegram 官方掌控。官方方案强调隐私友好、上下文投放和公开频道场景。它证明了一件事：Telegram 广告交易本身是成立的。([Telegram广告平台][1])

但你的机会不在复制官方，而在补官方没覆盖好的地方：

* 中文 Telegram 频道生态高度依赖非标准化的直接谈单
* 很多频道主不会招商，也不想天天私聊谈价格
* 很多广告主缺少稳定的频道池与统一执行标准
* 需要更灵活的频道偏好控制、广告频率控制和结算方式
* 需要更适合 bot/频道跳转/私聊 start 参数/进群等站内行为的追踪体系

第三方平台已经证明“频道主接 bot 接入广告市场”这条路有人在走，说明这个产品方向不是空想。你真正要做的是：不做一个粗糙的中介，而做一个对中文 Telegram 生态更顺手、更透明、更讲究控制权的平台。([Telega][2])

---

## 4. 平台的第一性原理

这个平台成败，不取决于“今天发了多少广告”，而取决于四个长期指标：

1. 频道留存率
   频道主接入后，是否愿意持续留在平台。

2. 广告主复投率
   广告主投过一次后，是否愿意再投。

3. 用户干扰度
   广告是否让频道用户明显反感，从而伤害频道。

4. 有效动作率
   广告是否真的带来站内或站外的可验证行为。

所以平台核心原则必须是：

* 对广告主：结果可解释
* 对频道主：控制权足够大
* 对平台：履约和账务要硬
* 对用户：广告密度必须受控

## 5. 核心角色定义

### 5.1 广告主 Advertiser

提交广告、设置预算、查看投放和效果、承担广告合规责任。

### 5.2 频道主 Publisher

接入频道、配置广告偏好、授权机器人投放、获取收益。

### 5.3 平台运营方 Operator

审核广告、处理频道入驻、处理争议、设定规则、管理账务和风控。

### 5.4 最终用户 Audience

看到广告并产生阅读、点击、私聊、加入频道、加入群组、使用 bot 等行为的人。

注意：最终用户不是平台“卖出去的商品”。
平台卖的是“可信分发机会”，不是“用户所有权”。

## 6. 产品结构总图

建议拆成 8 个能力域。

### 6.1 账户与身份域

负责谁是谁。

对象包括：

* 平台管理员
* 广告主账户
* 频道主账户
* 平台内部财务/审核员/客服
* 机器人实体
* 频道资产

这里要提前支持“一个账户下多个频道”和“一个频道可绑定一个收益主体”。

### 6.2 频道接入与画像域

负责频道为什么能接广告、接什么广告、一天接多少广告。

核心字段建议：

* 频道 ID
* 频道 @username / 链接
* 语言
* 内容类目
* 地区标签
* 是否公开频道
* 订阅量
* 近 30 天更新频率
* 平均阅读区间
* 接受广告类目
* 拒绝广告类目
* 每日广告上限
* 广告发布时间窗
* 自动接单 / 半自动 / 人工确认
* 履约评分
* 风险评分
* 结算状态

### 6.3 广告订单域

负责广告主如何买。

对象建议分层：

* Campaign：广告活动
* Ad Creative：具体广告素材
* Targeting Rule：投放偏好
* Budget Wallet：预算
* Placement Batch：实际分配批次
* Delivery Record：实际投放记录

不要把“广告”和“投放执行”混成一张表，否则后面一定乱。

### 6.4 审核域

包括：

* 文案审核
* 链接审核
* 目标频道/目标 bot 审核
* 行业风险审核
* 频道适配审核
* 重复投放审核

前期人审为主，规则机辅助。

### 6.5 匹配与调度域

负责把广告和频道配对。

平台初期不要做复杂算法，先做规则引擎：

* 行业匹配
* 语言匹配
* 频道偏好匹配
* 预算匹配
* 频道库存匹配
* 当日广告频率限制
* 同类广告冷却期
* 广告优先级
* 渠道质量优先级

### 6.6 投放执行域

机器人执行：

* 获取待投广告
* 检查频道权限
* 在时间窗内发布
* 记录 message_id
* 标记成功/失败
* 失败重试
* 记录删除或手动撤回事件
* 监控频道踢 bot / 失权

Telegram 对 bot/频道管理员权限是有明确模型的，频道管理员权限包括发消息、编辑消息、删除消息等；这意味着你要把“机器人是否拥有足够权限”当成正式数据模型，而不是部署前手工约定。([Telegram][3])

### 6.7 计量与结算域

这是平台像不像平台的关键。

最少需要：

* 广告主主账户余额
* 广告冻结金额
* 实际消耗流水
* 频道主待结算余额
* 已结算金额
* 平台服务费
* 退款流水
* 人工调整流水
* 争议冻结流水

### 6.8 风控与争议域

负责：

* 异常阅读识别
* 异常点击识别
* 广告主违规
* 频道主刷量
* 广告被秒删
* 频道不按规则履约
* 数据争议处理
* 退款或拒付流程

## 7. 交易模型设计

### 7.1 平台中的标准交易单位

建议把交易单位设计成三层：

#### 第一层：广告活动 Campaign

一次完整推广需求。
例如：推广某个频道、某个 bot、某个活动、某个产品。

#### 第二层：广告素材 Creative

某条具体消息内容。
包括文案、按钮、链接、图片/视频、落地目标。

#### 第三层：投放批次 Placement Batch

把某个素材投到一组频道的执行计划。

这样做的好处是：
广告主可以一个活动下面挂多个素材；
平台可以对同一素材做多批次分发；
结算和报表也能清晰拆开。

---

## 8. 广告类型定义

第一版建议只支持 4 种，不要一上来过多。

1. 频道引流广告
   目标是引导用户订阅某 Telegram 频道。

2. 群组引流广告
   目标是引导用户加入群组。

3. bot 启动广告
   目标是让用户点击按钮并触发 bot deep link /start 参数。

4. 外链跳转广告
   目标是访问外部页面。

这 4 种已经足够覆盖大多数场景。
先别做“表单广告”“多步漏斗广告”“复杂 CPA 广告”。

---

## 9. 频道接入模型

频道侧是供给端，必须让接入足够轻，但控制权足够强。

### 9.1 频道接入流程

1. 频道主私聊 AdWorker bot
2. 选择“接入频道赚钱”
3. 机器人要求把 bot 拉进目标频道并授予所需权限
4. 平台验证机器人确实在频道且具备权限
5. 频道主填写频道基础资料
6. 平台人工审核频道
7. 审核通过后进入“可接单”状态

### 9.2 频道主必须可配置的参数

* 每日最多广告数
* 广告允许发布时间段
* 拒绝的类目
* 敏感词黑名单
* 是否接受外链
* 是否接受引流到其他频道
* 是否接受引流到 bot
* 是否允许按钮
* 是否允许带图片/视频
* 自动接单 / 半自动 / 手工确认
* 广告与正常内容最小间隔
* 节假日或特殊时段暂停投放

这部分是平台差异化关键。
频道主越有控制感，越不容易流失。

### 9.3 频道分级

建议第一版就做等级，但不要公开太复杂。

内部等级建议：

* S：高质量优先频道
* A：稳定频道
* B：普通频道
* C：观察频道
* R：风险频道

评级依据不要只看订阅量。
至少综合以下几项：

* 更新频率
* 阅读稳定性
* 历史履约率
* 广告后删除率
* 争议率
* 用户响应质量
* 风险记录

## 10. 广告主模型

### 10.1 广告主接入流程

1. 广告主私聊 bot 或进入后台
2. 注册账户
3. 提交基本身份资料
4. 充值
5. 创建广告活动
6. 提交素材
7. 通过审核
8. 开始投放

### 10.2 广告主必须看到的不是“发了多少条”，而是：

* 钱花到哪里了
* 哪些频道在发
* 哪些频道效果更好
* 哪些素材表现更好
* 消耗进度
* 异常说明
* 可暂停和继续

### 10.3 广告主可配置项

* 总预算
* 日预算
* 类目
* 语言
* 投放时间窗
* 是否允许新频道参与
* 是否只投某些频道等级
* 是否允许外链
* 投放目标类型
* 素材 A/B 版本

## 11. 审核体系

你这个平台能不能长期活，很大程度取决于审核。

### 11.1 广告审核维度

* 行业是否合法
* 是否诈骗风格
* 是否误导性强
* 是否涉及违禁内容
* 文案质量是否太低
* 落地链接是否异常
* 是否适合目标频道受众
* 是否重复轰炸

Telegram 自身条款也明确禁止 spam、scam 和多数国家认定的非法活动。你自己的平台规则必须至少不低于这个底线。([Telegram广告平台][4])

### 11.2 建议的行业白名单/灰名单/黑名单

第一版建议：

白名单：

* 正常频道推广
* 正常 bot 推广
* 正常产品宣传
* 正常活动宣传

灰名单：

* 金融相关
* 医疗相关
* 博彩边缘类
* 成人擦边类
* 高承诺收益类

黑名单：

* 明显诈骗
* 非法博彩
* 假冒平台
* 非法商品/服务
* 虚假承诺拉人头项目
* 恶意跳转 / 钓鱼

第一版宁可保守，也不要为了接单把平台名声做坏。

## 12. 匹配与投放策略

### 12.1 第一版不要做算法神话

先做规则匹配。

匹配条件：

* 广告类目 ∩ 频道接受类目
* 广告语言 = 频道语言
* 预算 ≥ 频道最低可投阈值
* 频道当天库存未满
* 频道时间窗允许
* 同类广告冷却期满足
* 风险评分不过线

### 12.2 渠道库存定义

频道库存不是无限的。
建议第一版强制定义：

* 每频道每日广告最大条数
* 连续两条广告最小间隔
* 广告占频道总内容比例上限
* 特殊节日/活动期间例外规则

这一层一定要写死为平台能力，否则后面必然烂量。

### 12.3 投放顺序建议

先投：

1. 高履约率频道
2. 与广告主题更贴近频道
3. 历史转化表现更好的频道
4. 当日广告密度较低频道
5. 价格更优频道

不要一开始就只按最便宜的发。
那样广告主短期可能高兴，平台长期会劣化。

## 13. 计量体系

这是最关键部分之一。

你前面一直强调“广告主要真用户，不要假流量”，这个方向对。但不要在第一版就承诺“我能精准还原最终成交”。那很容易出虚假承诺。

### 13.1 建议的四层计量

#### 第一层：履约计量

平台是否真的发出去了。

指标：

* 发布时间
* 发布频道
* message_id
* 是否成功
* 是否被删除
* 存活时长

#### 第二层：站内可见反馈

Telegram 内能看到的基础反应。

指标可包括：

* 阅读增量
* 按钮点击
* bot deep link 触发
* 加入群/频道动作
* 私聊 bot 的 /start 参数命中

#### 第三层：平台内归因动作

你能直接记录到的平台内行为。

例如：

* 点击广告按钮进入 bot
* bot 内完成注册
* bot 内提交联系方式
* bot 内领取码

#### 第四层：站外回传

广告主自己系统回传。

例如：

* 注册成功
* 下单成功
* 支付成功

### 13.2 第一版推荐的计费依据

不要纯按“阅读量”结算。
更稳妥的是混合式：

* 基础履约费
* 外加可验证动作奖励

例如：

* 广告成功发布且存活超过 N 小时，产生基础费用
* 若带来 bot start、加群、订阅等动作，再追加效果费用

这样做的好处是：

* 基础履约有底
* 效果好的频道会自然赚更多
* 比纯阅读更容易解释
* 比纯成交归因更容易落地

## 14. 账务与结算体系

这部分必须一开始就做对，不然后面全是技术债。

### 14.1 广告主账务

广告主资金状态建议至少分为：

* available_balance 可用余额
* reserved_balance 冻结余额
* spent_balance 已消耗
* refunded_balance 已退款

流程：

1. 广告主充值
2. 创建投放时预冻结预算
3. 每条投放履约后按规则扣费
4. 未执行部分解冻
5. 争议订单先冻结

### 14.2 频道主账务

频道主收益状态建议至少分为：

* pending_earnings 待确认收益
* confirmed_earnings 已确认收益
* frozen_earnings 争议冻结收益
* settled_earnings 已结算收益

流程：

1. 广告成功投放后先进入待确认
2. 过观察期后转已确认
3. 到结算周期后打款
4. 争议订单可冻结

### 14.3 平台账务

平台要有：

* service_fee 服务费
* adjustment 调账
* compensation 补偿
* manual_refund 人工退款
* dispute_reserve 争议准备金

哪怕前期费率很低，也要把账本结构先建好。
否则你以后根本没法健康扩张。

---

## 15. 风控体系

### 15.1 风控目标

不是“完全杜绝作弊”，而是：

* 提高作弊成本
* 降低大规模作弊收益
* 给争议处理提供依据
* 保护广告主复投意愿
* 保护优质频道不被劣币驱逐

### 15.2 第一版必须覆盖的风险

1. 频道刷阅读
2. 广告主提交欺诈落地页
3. 广告被频道主秒删
4. bot 被踢或丢权限
5. 同一广告短期重复轰炸
6. 低质广告伤害频道体验
7. 人工客服乱改账
8. 平台统计口径不透明

### 15.3 第一版可执行的风控规则

* 广告发布后短时间内被删除，进入人工复核
* 某频道广告后阅读曲线长期异常，降级
* 同类广告在同频道短周期重复，拦截
* 被投诉次数过多广告主，暂停账户
* bot 失权自动停投该频道
* 高风险行业强制人工审核
* 结算前保留观察期

## 16. 争议处理机制

平台型产品必须允许争议，但不能允许争议无限蔓延。

### 16.1 典型争议场景

* 广告主说效果差
* 频道主说平台扣费不合理
* 广告被删了但谁删的不清楚
* 广告主说素材被改坏了
* 平台怀疑刷量
* 频道主说广告不符合自己设置

### 16.2 处理原则

* 先看履约事实
* 再看配置与规则
* 再看平台日志
* 最后才是人工裁定

因此必须有：

* 配置快照
* 广告审核记录
* 投放日志
* message_id 与时间戳
* 删除事件
* 账务流水
* 人工处理备注

没有这些记录，争议处理永远靠吵架。

## 17. 核心流程设计

### 17.1 频道接入流程

接入 → 验证权限 → 填资料 → 审核 → 配置偏好 → 上线

### 17.2 广告投放流程

充值 → 创建活动 → 提交素材 → 审核 → 匹配频道 → 冻结预算 → 执行投放 → 记录履约 → 观察期 → 结算/退款

### 17.3 争议流程

发起争议 → 暂停结算/冻结 → 平台查看日志 → 人工裁定 → 调整账务 → 结案

## 20. MVP 范围

这里是最重要的部分。
不要把第一阶段做成幻想版开放平台。

### MVP 目标

做出一个“邀约制、半自动、可闭环”的广告联盟。

### MVP 必须包含

1. 频道接入

* 频道主通过 bot 绑定频道
* 频道配置广告偏好
* 平台审核通过

2. 广告创建

* 广告主创建广告
* 平台人工审核

3. 基础匹配

* 按类目、语言、库存、偏好规则匹配频道

4. 自动投放

* bot 在频道发广告
* 记录 message_id 与状态

5. 基础效果记录

* 履约成功
* 消息存活
* 基础可见数据
* bot start / join 等可追踪动作

6. 账务

* 广告主充值
* 冻结/扣费
* 频道收益累计
* 手工结算

7. 人工争议处理

* 暂停订单
* 冻结账务
* 手工裁决

### MVP 不做

* 开放市场大厅
* 实时竞价
* 复杂推荐算法
* 复杂外部归因
* 多币种自动结算
* 完整外部 API
* 复杂分销体系

## 21. 三阶段路线图

### Phase 1：自用闭环

目标：你自己的广告需求 + 你自己控制的频道池先跑通。

验收标准：

* 广告能创建、审核、发布、记账、出基础报表
* 频道能绑定、配置、接单、看收益
* 平台能人工处理异常

### Phase 2：小范围联盟

目标：引入少量可信外部频道主和少量可信广告主。

新增重点：

* 频道评级
* 更稳定的账务与结算
* 半自动风控
* 更完整报表
* 周期性结算

### Phase 3：开放平台化

目标：开放更多外部用户自助接入。

新增重点：

* 自助注册与准入规则
* 更强审核流水线
* 更复杂匹配引擎
* 公开产品文档
* 标准化服务费规则
* 品牌与客服体系

## 22. 护城河设计

不要把护城河想成“强制排他”。

更稳的护城河有 5 个：

1. 高质量频道供给
2. 稳定结算和透明账务
3. 数据积累后的匹配效率
4. 更低打扰的广告体验
5. 广告主复投习惯

你可以后期再考虑排他条款，但前期不建议靠这个做主策略。
前期最重要的是让平台“值得留下来”。

## 23. 平台公开承诺建议

平台要想长，必须有公开原则。

建议第一版就写清楚：

* 不接明显诈骗和非法广告
* 广告密度受控，不允许无限刷屏
* 频道主有最终偏好控制权
* 广告主的预算、消耗、渠道分布透明
* 频道主收益可核对
* 争议有流程，不靠口头扯皮
* 平台有服务费规则，不暗扣

这些不是文案，而是产品信用。

## 24. 你这个项目最容易失败的几种方式

我直接指出来。

第一，一上来做得太开放。
结果审核跟不上，频道质量参差不齐，广告主被骗一次就走。

第二，只看发单量，不控广告密度。
短期收入涨，频道体验迅速恶化，供给端流失。

第三，账做不硬。
一旦结算和争议处理混乱，平台信誉直接崩。

第四，过早承诺“真实转化”。
如果你没有可靠归因体系，这句话会反噬你。

第五，把平台做成低价垃圾广告集散地。
短期接单容易，长期没有优质频道愿意留下。

## 25. 我给你的最终定版建议

如果你要把 AdWorker 做得“有模有样，真的拿得出手”，那核心不是把机器人写得多炫，而是把下面四样一次做对：

一，交易对象定义对
卖的是可信分发，不是虚构用户。

二，账本结构对
广告主、频道主、平台三方账一定要硬。

三，频道控制权设计对
频道主必须有足够强的频率、类目、时间和格式控制权。

四，争议与风控机制对
平台必须能处理“发了但效果差”“数据异常”“广告被删”“预算争议”。

只要这四层立住，后面 UI、策略、算法、开放平台，都是往上加的事。
