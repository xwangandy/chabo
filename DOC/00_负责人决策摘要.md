## 一、 核心商业判断：为什么做、靠什么赢、怎么赚钱？

1. **市场空隙真实存在（为什么做）**
   - **官方 Telegram Ads** 限制 160 字纯文本且**严禁跳转外部网站**，把独立站、App 下载、重度种草客户全部挡在门外；
   - **海外平台（Telega.io / AdsGram）** 缺乏中文垂类优质频道，且不管“刷量假粉”死活，外链直跳在手机端易弹警告导致流失率高；
   - **中文圈私聊中介** 假截图泛滥、沟通排期极慢、秒删帖无保障。
   - **插播的生态位**：做中文 Telegram 垂类频道的**「可信履约 + 脱水归因 + 高复购代投及交易平台」**。

2. **财务测算揭示的残酷真相（怎么赚钱）**
   - 利润模拟证明：如果早期没有自有频道，纯靠撮合第三方频道收 **8%** 佣金，每月必须撮合 **\$32,600+ GMV（约 163 单）** 才能养活 1 个全职运营！
   - 反之，依托你手头的 **`TelegramABC` 自有频道矩阵（近 100% 毛利）+ 15%～25% 代投策划服务费**，每月仅需 **3.5 单（约 \$700 GMV）** 即可跨过盈亏平衡线，月均 55 单时即可产生约 **\$3,600+/月** 的稳健净利。
   - **正确演进路径**：**先卖自有频道联投套餐赚高毛利现金流 $\rightarrow$ 靠广告底部的 `[📣 频道招商]` 按钮免费裂变吸纳新广告主与外部频道 $\rightarrow$ 用溢出的真实预算收编第三方频道赚担保抽佣**。

## 二、 对 R1 / R2 及现有代码的四大纠偏（避坑指南）

1. **【纠偏 R1 工程路线】绝不新建 `chabo-next` 从零重写，直接在现有 `ChaBo` 原位升级**
   - 实测现有 `ChaBo` 代码库 `189` 个自动化测试中 `184` 个核心账本、权限、三端网页测试全部通过。
   - R1 担心的“发帖超时重复发送”问题（位于 `src/chabo/fulfillment.py` 第 32～196 行），在同仓库的 `SelfPromoService`（`src/chabo/services/channel.py` 第 960 行）中已有成熟的“事务外发送”标准写法，**仅需半天（约 80 行代码）即可修好**，推倒重写会白白浪费 1～2 个月工期。
2. **【纠偏 R2 技术断言】“站内探针 `/start`” $\neq$ “100% 人类真人”**
   - 站内深链（`t.me/bot?start=ad_x`）确实能 **100% 免疫 HTTP 链接预览爬虫并拿到真实 `telegram_user_id`**，但黑产可用 MTProto Userbot 僵尸号矩阵脚本批量发送 `/start`。
   - **修正方案**：对外严禁宣传“100% 真人”，统称「实名账号去重互动」；对内叠加**“账号属性检查 + 点击时间分布熵 + 详情页二跳率 + 跨频道黑名单”**四重防刷过滤。
3. **【纠偏跳转设计】目的地是 `t.me` 时，严禁套用 `/r/{token}` HTTP 短链！**
   - 用外部 HTTPS 短链跳回 `t.me/频道或Bot`，会在苹果/安卓端触发外链弹窗警告与浏览器二次拉起，流失率高达 30%～50%。
   - **铁律**：跳外部独立网站用 **`/r/{token}` 302 短链**；跳 Telegram 内部频道/Bot 必须用 **专属邀请链接（`createChatInviteLink`）** 或 **站内详情页二跳**。
4. **【纠偏现有代码】立即拆除“广告主付费墙”与修复“评分满分膨胀”**
   - 现有代码要求广告主先花钱买 Pro 会员才能批量下单和看完整报表，在早期等于把金主往门外推——**V1 必须对充值广告主 100% 免费开放选号、批量下单与完整结案报告**！
   - 现有 `PricingService.assess_channel()` 算法导致数据库里 3 个演示频道全部算出 `100` 分满分，必须按《报告 04》重构为「质量分 + 样本置信度 + 刷量风险灯」。

## 三、 插播 V1 最终范围裁决：做什么 vs 不做什么

| 类别 | V1 立即做（最小赚钱与复购闭环） | V1 坚决不做（防泥潭、防封号、防亏损） |
| :--- | :--- | :--- |
| **核心产品与交互** | 沿用现有三端 React 网页（管理端/广告主端/频道主端）+ **新增免登录只读结案报告页（`/public/reports/:token`）** | 不再扩充 `bot.py` 多步菜单；彻底停用“文字插播”；不在早期对广告主设会员付费墙 |
| **渠道与交易履约** | 导入 `TelegramABC` 自有频道打包售卖 + 预充值硬账本（OTC 双人复核入账）+ **修复 `fulfillment.py` 防重发状态机** | 不做无担保赊账后付；不做自动链上充提热钱包；不开放无审核自动发帖 |
| **数据采集与归因** | **双轨归因**：站内 `[🔍 查看详情]` 探针 + 站外 `/r/{token}` 四层防刷短链 + 1h/6h/24h 浏览量快照与防删帖巡检 | 不抓未授权公开频道（防封号）；不承诺全量独立覆盖人数；不在无商户配合时伪造 CPA/ROI |
| **智能优化与裂变** | **同场频道红黑榜对比** + 贝叶斯平滑评分 + 报告底部 **`[🚀 按红榜频道一键复投]`** + 广告帖底部 **`[📣 频道招商]`** 裂变入口 | 不做小样本下必然失效的自动 tCPC/tCPA 竞价；不把 Telegram 接口数据喂给外部大模型训练 |

## 四、 第一阶段验证路线（先验证什么？）

在写任何新功能代码前，按以下 **4 个顺序步骤** 推进：

1. **第 1 步（资产摸底 · 1天）**：导出你手头 `TelegramABC` 真实自有频道清单（频道名、订阅数、24h 浏览中位数、历史接单价），填入 `ChaBo` 替换掉当前的 6 个测试频道，设计出首批 2～3 个「行业联投套餐包」。
2. **第 2 步（真机跳转与采样实验 · 1～2天）**：在 2 个自有频道实测 iOS / Android 点击「站内二跳详情」与「`/r/{token}` 跳外部网页」的弹窗体验，并验证通过 `TelegramABC` 的 MTProto 接口读取 `channels.getMessages`（`message.views`）的稳定性。
3. **第 3 步（外科手术式代码补齐 · 5～7天）**：
   - ① 修复 `src/chabo/fulfillment.py` 事务外发帖与异常对账状态；
   - ② 解除广告主报表与批量下单的 Pro 付费墙限制，修正频道评分满分膨胀；
   - ③ 新增 `/r/{token}` 短链防刷跳转、1h/6h/24h 浏览量快照任务、以及带 `[一键复投]` 的免登录结案报告页。
4. **第 4 步（首单真金白银验证）**：用自有频道矩阵接第 1 单真实付费广告，交付第一份带 V/P/R 分级与同场红黑榜的结案报告，验证客户是否认可报告并产生复投。
