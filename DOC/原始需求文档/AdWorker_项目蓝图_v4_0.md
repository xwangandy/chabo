# AdWorker 项目蓝图 v4.0

## 从"设计正确"到"活下来"——经过红队审视后的生存型蓝图

\---

# 上篇：红队审视——v3.0 容易死在哪里

在写 v4.0 之前，必须先站在反方把 v3.0 的致命问题摊开讲。v3.0 在架构设计上是完整的，但"设计完整"和"能活下来"是两回事。以下是站在投资人、竞争对手、现实执行者三个视角看到的 **八个致命弱点**。

\---

## 致命弱点一：冷启动方案是空话

**问题本质：** v3.0 说"先自用闭环"，但自用闭环意味着你既是广告主又是频道主，你在跟自己做交易。这不叫验证产品，这叫自嗨。

**具体表现：**

* "自有频道 + 自有广告需求"跑通的闭环，完全无法验证外部频道主是否愿意接受 CPC/CPA 模式。你自己的频道不会秒删广告，不会刷量，不会嫌钱少——但真实频道主会。
* v3.0 的"冷启动激励"（前 30 天保底收益、前 10 条免抽佣）听起来不错，但算一笔账：如果你接入 50 个频道，每个频道每天 2 条广告，保底每条给 $0.5，一个月烧 $1,500。问题是这 $1,500 换来了什么？如果此时广告主只有你自己，广告库存严重不足，频道主拿了保底钱之后发现"根本没广告可发"，体验比没有保底更差。
* 冷启动的真正死因不是"没钱补贴"，是**匹配密度不够**：广告太少，频道太多，每个频道一天分不到一条广告。频道主的体验是"装了你的 bot 然后什么都没发生"。

**致死概率：70%** — 这是双边平台最常见的死法，绝大多数双边市场死在冷启动阶段。

\---

## 致命弱点二：CPC/CPA 模式对频道主的吸引力被严重高估

**问题本质：** v3.0 把"放弃 CPM、转向 CPC/CPA"当作核心战略优势，但这个判断忽略了一个现实——频道主不喜欢 CPC/CPA。

**具体表现：**

* 频道主的思维方式是："我有 5 万订阅者，一条广告帖能给我带来 3 万阅读，这个注意力值多少钱？"他不会接受"帖子发了，阅读 3 万，但只有 200 人点击，所以你只赚了 200 × $0.05 = $10"这种账。
* 在现有的 Telegram 广告市场中，频道主通过私聊谈单，一条广告帖的报价通常是 $50-$500（取决于频道大小）。如果你告诉他"来我们平台，按点击给你算钱，每次点击 $0.03-$0.10"，他会算出每条广告大概只能赚 $5-$30，远低于直客价。
* "Guarded Hybrid"模式（保底 + 效果）听起来折中，但如果保底太低（比如 $2/条），频道主会觉得是侮辱；如果保底太高（比如 $30/条），平台的风险全压在自己身上，广告主还没付出有效动作就已经亏钱了。
* **核心矛盾：CPC/CPA 保护了广告主，但把风险转嫁给了频道主。而冷启动阶段你最缺的恰恰是频道主。**

**致死概率：60%** — 如果你招不到足够多的频道主，平台没有供给，广告主也不会来。

\---

## 致命弱点三：技术复杂度与团队现实严重不匹配

**问题本质：** v3.0 描述了一个包含 10 个能力域、30+ 数据表、302 网关、bot 中继、四层风控、观察期结算的系统。这不是一个 MVP，这是一个中型 SaaS 的完整版。

**具体表现：**

* 302 网关短链服务需要独立的 HTTP 服务、低延迟保障、click dedup 逻辑、UA/IP 解析。这本身就是一个独立项目。
* Bot 中继归因需要处理 Telegram API 的 rate limiting、callback 超时、用户在中继过程中退出等边缘情况。
* 四层风控（阅读 + 点击 + 转化 + 履约）需要大量的历史数据来训练阈值。在 Phase 1 根本没有数据的情况下，这四层风控形同虚设。
* 观察期结算的"存活心跳检查"需要持续轮询 Telegram API 检查 message\_id 状态，这本身会受到 rate limit 限制。如果你有 1000 条活跃广告在观察期内，每小时检查一次就是 1000 次 API 调用。
* **一个 2-3 人的初创团队，在 3 个月内根本不可能同时做好这些事情。**

**致死概率：50%** — 不是死于做不出来，而是死于"做了太多，每个都半成品"。

\---

## 致命弱点四：与现有竞争者的差异化不清晰

**问题本质：** v3.0 大量篇幅描述了"怎么做"，但几乎没有回答"为什么广告主/频道主要选你而不是现有方案"。

**具体表现：**

* Telegram 生态中已经存在多个第三方广告平台：Telega.io 提供频道广告撮合，RichAds 和 PropellerAds 提供 Mini App 内广告，AdsGram 专注 Mini App 广告。2026 年市场上已经是红海。
* 对于大型频道主，直客模式（直接和广告主谈）的收入远高于任何平台。他们没有动力接入一个新平台。
* 对于小型频道主，他们的阅读量太低，按 CPC 算根本赚不到钱，不如不接广告。
* 对于广告主，现有的"找频道主私聊谈单"虽然麻烦，但灵活度极高，可以谈到非常定制化的合作方式。你的平台标准化了流程，但也标准化了限制。
* **v3.0 没有回答一个关键问题：你的"白热中心"（white-hot center）在哪里？谁是你的第一批 10 个最忠诚的用户？**

**致死概率：40%** — 如果你找不到一个足够窄的切入点，你会在"通用平台"的道路上被已有玩家碾压。

\---

## 致命弱点五：收入模型在 Phase 1-2 无法支撑运营

**问题本质：** v3.0 的收入来源——点击/动作抽佣、技术服务费、风控服务费——在早期交易量极低的情况下接近于零。

**具体表现：**

* 假设 Phase 1 有 10 个频道，每天每频道 2 条广告，每条广告产生 100 次有效点击，CPC $0.05，平台抽佣 20%。日收入 = 10 × 2 × 100 × $0.05 × 20% = $20/天 = $600/月。
* 这 $600/月 连一个服务器都不够租，更不用说团队工资。
* v3.0 提到"前期可以极低费率"，但没有回答一个核心问题：\*\*Phase 1-2 靠什么活着？\*\*如果靠融资，那融资故事是什么？如果靠创始人自掏腰包，能撑多久？
* 更重要的是，如果你前期不收费或极低收费，你如何向广告主和频道主证明你是一个"认真的平台"而不是一个"随时可能关停的实验项目"？

**致死概率：55%** — 创业公司最常见的死因之二就是现金流断裂。

\---

## 致命弱点六：争议处理的人力成本被严重低估

**问题本质：** v3.0 设计了完美的争议处理机制（证据链、快照、仲裁），但没有算过这需要多少人力。

**具体表现：**

* 在一个效果型广告平台上，争议率通常在 5%-15%。如果你每天有 200 条广告投放，就意味着每天 10-30 条争议需要处理。
* 每条争议需要查看：素材快照、频道配置、点击日志、message\_id 状态、风控结论。保守估计每条处理 15-30 分钟。
* 这意味着每天需要 2.5-15 小时的人工争议处理时间。在 Phase 2（50-100 个频道）阶段，这可能需要 1-2 个全职客服。
* **但 Phase 2 的收入（按前面的估算）可能只有 $2,000-$5,000/月，根本雇不起客服。**
* 如果争议处理不及时，广告主和频道主都会丧失信心。这是一个"越认真设计争议机制、越需要人力投入、越难在早期实现"的悖论。

**致死概率：35%** — 不会直接致死，但会严重拖慢增长。

\---

## 致命弱点七：对 Telegram API 的依赖构成平台风险

**问题本质：** AdWorker 的一切能力都建立在 Telegram Bot API 之上。Telegram 一旦改变 API 策略，平台可能在一夜之间失效。

**具体表现：**

* Telegram 可以随时修改 bot 的权限模型、频率限制、message 查询接口。
* Telegram 已经在 2024 年加强合规执行，Pavel Durov 被捕后平台开始向执法部门共享用户数据。如果 Telegram 决定限制第三方广告 bot 的行为（比如限制 bot 在频道中发送的消息频率，或要求广告 bot 必须通过官方审核），AdWorker 的整个业务模型可能被釜底抽薪。
* Telegram 官方广告平台本身也在持续降低门槛（最低投放金额已从最初的数百万欧元降至数百欧元），如果继续降低并开放更多广告形式，第三方平台的生存空间会被进一步压缩。
* **v3.0 没有任何"Plan B"来应对这个系统性风险。**

**致死概率：25%** — 概率不高但一旦发生是毁灭性的。

\---

## 致命弱点八：蓝图本身过于宏大，执行者容易迷失

**问题本质：** v3.0 是一份 excellent 的"终局设计"，但不是一份好的"起步指南"。

**具体表现：**

* 19 个章节、10 个能力域、30+ 数据表、4 种计费模式、3 种接单模式、5 级频道评级、4 层风控、3 阶段路线图——信息量巨大，但执行者看完之后最可能的反应是"不知道明天应该先写哪行代码"。
* v3.0 的 MVP 定义仍然包含 7 项"必须做的事"，每一项都是一个完整的子系统。这不是 MVP，这是"最小可体面产品"（Minimum Viable Impressive Product）。
* **真正的 MVP 应该能在一句话里说清楚：第一天上线时，用户能做什么？不能做什么？**

**致死概率：30%** — 死于"完美主义导致的永远上不了线"。

\---

# 下篇：AdWorker v4.0——生存优先的实战蓝图

v4.0 不推翻 v3.0 的终局设计，而是在 v3.0 的骨架上做三件事：

1. **砍掉 Phase 1 中一切不必要的复杂度**
2. **重新设计冷启动策略，从"补贴思维"转向"自用即产品"思维**
3. **为每个阶段设定明确的生死线指标**

\---

## 第一部分：重新定义项目——从"平台"退回"工具"再长成"平台"

### 1.1 认知校正

v3.0 最大的认知错误是**从第一天就把自己当成平台**。

现实是：没有交易量的平台不是平台，是一个没人用的网站。

正确的路径不是"设计平台 → 招募两端 → 启动交易"，而是：

```
做一个自己用的工具 → 工具足够好，别人也想用 → 
一对多变成多对多 → 多对多就是平台
```

这是 OpenTable、Shopify、Amazon 的共同路径：先做单边价值，再长出双边网络效应。

### 1.2 v4.0 的定位分阶段变化

|阶段|定位|一句话描述|
|-|-|-|
|**Phase 0**（新增）|自用投放工具|"我自己的广告，用 bot 高效投到我自己和朋友的频道里"|
|**Phase 1**|频道主 SaaS 工具|"频道主接入后，自动收到匹配的广告，自动记账，自动结算"|
|**Phase 2**|受邀广告联盟|"广告主和频道主通过平台撮合交易，平台保障履约"|
|**Phase 3**|开放效果市场|"按 CPC/CPA 自动交易、按信用自动分发的效果广告市场"|

关键变化：**新增 Phase 0**。这不是产品阶段，是生存阶段。

\---

## 第二部分：Phase 0——自用即产品（0-6 周）

### 2.1 Phase 0 的唯一目标

**你自己就是第一个广告主，你自己的频道和朋友的频道就是第一批供给。**

Phase 0 结束时要回答一个问题：**这个工具是不是比你现在手动在频道里发广告更好用？**

如果连你自己都不觉得好用，别人更不会用。

### 2.2 Phase 0 只做 4 件事

**1. Bot 能在频道里发消息并记录 message\_id**

不需要 302 网关，不需要中继 bot，不需要风控。就是：创建一条广告 → 选择频道 → bot 发出去 → 记录发送时间和 message\_id → 检查 24 小时后是否还活着。

**2. 广告带上可追踪的 deep link 按钮**

所有按钮都用 `t.me/YourBot?start=ad\_{id}\_{channel\_id}` 格式。当用户点击后，bot 收到 /start 命令，解析参数，写入数据库。这就是最简单的归因——零外部依赖。

**3. 一个极简的记账页面**

不需要预冻结、微结算、观察期。就是：这条广告花了多少钱 → 产生了多少次 bot start → 每次 start 成本是多少。一个 Google Sheet 都够了，但最好做成 bot 内的查询命令。

**4. 频道配置：每天最多几条，什么时间发**

这是为后面自动化做的最小基础设施。

### 2.3 Phase 0 不做的事

* ❌ 302 网关
* ❌ 中继 bot 重定向
* ❌ 风控系统
* ❌ 频道评级
* ❌ 争议处理
* ❌ 广告审核流程
* ❌ Web 后台
* ❌ 多计费模式
* ❌ 频道主收益结算

### 2.4 Phase 0 的生死线

|指标|及格线|说明|
|-|-|-|
|投放成功率|> 95%|bot 发出去的消息有 95% 成功|
|bot start 归因准确率|100%|每一次 start 都能正确归因到广告和频道|
|你自己是否觉得好用|主观判断|如果你自己还是更喜欢手动发，项目方向可能有问题|

**Phase 0 的时间框：6 周。超过 6 周还没上线，说明做了太多。**

\---

## 第三部分：Phase 1——从工具长出单边价值（6 周-4 个月）

### 3.1 Phase 1 的核心转变

Phase 0 验证了"自己用好用"之后，Phase 1 的目标是让**外部频道主觉得有价值**。

但注意：Phase 1 不是让频道主"接广告赚钱"（那需要广告主供给），而是让频道主获得一个**独立于广告的单边价值**。

### 3.2 "单人模式"（Single-Player Mode）——频道主即使没有广告也能获得价值

这是解决冷启动问题的关键策略。参考 OpenTable（先给餐厅提供订座管理工具，再接入食客）和 Freightos（先给货代提供报价自动化工具，再接入买家）。

**给频道主的单人模式价值：**

**a) 频道健康诊断报告**

* bot 接入频道后，自动分析：阅读趋势、最佳发布时段、内容类型分布、订阅增长曲线
* 这个功能本身就有价值，很多频道主从来没见过自己频道的数据分析
* 免费提供，作为接入 bot 的即时回报

**b) 内容排期工具**

* 频道主可以通过 bot 预约发布自己的内容（不是广告，是自己的内容）
* 这是一个轻量级的频道管理工具，降低频道主的日常运营成本
* 让 bot 在频道里有持续存在的理由，而不是"装了之后等广告"

**c) 频道主社区与排行榜**

* 接入 bot 的频道主进入一个私密群组，分享运营经验
* 按阅读增长率、互动率等维度做频道排行榜
* 形成频道主之间的社区效应，增加留存

### 3.3 Phase 1 的广告能力（最小版本）

在"单人模式"跑起来之后，逐步引入广告：

**计费模式：只用一种——固定单价**

不是 CPC，不是 CPA，不是 Hybrid。就是**每条广告一个固定价格**。

为什么？因为：

* 频道主能确定地知道"我发一条赚多少钱"
* 广告主能确定地知道"我投一条花多少钱"
* 没有"点击算不算有效"的争议
* 没有复杂的归因系统依赖
* 定价由平台根据频道等级设定（S 级 $50/条，A 级 $20/条，B 级 $5/条）

**这和 v3.0 的"放弃 CPM"矛盾吗？不矛盾。**

固定单价本质上是一个简化的"保底履约费"。Phase 1 的目标不是建立效果市场，而是跑通"广告从广告主到频道的全流程"。效果计费是 Phase 2-3 的事。

**点击数据仍然记录，但不用于结算，只用于给广告主提供参考报表。** 这样既积累了数据，又不在早期引入结算争议。

### 3.4 Phase 1 新增的最小基础设施

|组件|说明|复杂度|
|-|-|-|
|简单短链|所有按钮链接加上 UTM 参数或 deep link 参数，不需要独立 302 网关|低|
|广告存活检查|每 6 小时检查一次 message\_id 是否存在|低|
|广告主 bot 面板|创建广告 → 选频道 → 付款 → 查看报表（bot 内完成）|中|
|频道主 bot 面板|查看今日广告 → 查看收益 → 设置偏好|中|
|简单账本|广告主充值 → 扣费（按条）→ 频道主累计收益 → 手动提现|中|

### 3.5 Phase 1 的生死线

|指标|及格线|说明|
|-|-|-|
|频道主接入数|≥ 20 个外部频道|不含自有频道|
|频道主 30 天留存率|> 60%|接入后一个月还没把 bot 踢掉|
|广告主数量|≥ 5 个外部广告主|不含自己|
|广告主复投率|> 50%|投过一次后愿意再投|
|月交易额|> $1,000|证明有人愿意花真钱|
|争议率|< 10%|固定单价模式下争议应该很少|

**Phase 1 的时间框：2-3 个月。如果 4 个月还没达到生死线，需要认真考虑是否 pivot。**

\---

## 第四部分：Phase 2——引入效果计费，成为联盟（4-10 个月）

### 4.1 Phase 2 的前提条件

只有在以下条件同时满足时才进入 Phase 2：

* Phase 1 的所有生死线指标达标
* 积累了至少 500 条广告投放的点击数据
* 有至少 3 个广告主明确表示"我愿意按点击付费"
* 有至少 10 个频道主明确表示"我愿意尝试效果计费"

### 4.2 Phase 2 的计费模型变化

**从"固定单价"过渡到"保底 + CPC 双轨"：**

```
频道主每条广告收入 = 保底履约费 + (有效点击数 × CPC 单价 × 频道分成比例)
```

**保底履约费不是象征性的，而是有意义的：**

|频道等级|保底履约费/条|CPC 分成|预期总收入/条|
|-|-|-|-|
|S 级|$30|$0.08 × 70%|$30 + \~$28 = \~$58|
|A 级|$12|$0.06 × 70%|$12 + \~$12 = \~$24|
|B 级|$3|$0.04 × 70%|$3 + \~$4 = \~$7|

这个定价的核心思路是：**保底收入占总预期收入的 40-50%**。这样频道主不会觉得"全靠点击太不确定"，广告主也不会觉得"全是保底在花冤枉钱"。

### 4.3 Phase 2 新增的关键能力

**a) 302 网关（此时才真正需要）**

因为 Phase 2 开始有外链广告和 CPC 结算需求，此时 302 网关的 ROI 才成立。

**b) 基础风控**

不是四层风控，是**两条规则**：

* 规则 1：同 IP 在 10 分钟内对同一广告的重复点击不计费
* 规则 2：已知数据中心 IP 段的点击不计费

只做这两条，已经能拦截 80% 的低级作弊。复杂风控留给 Phase 3。

**c) 观察期结算（简化版）**

* 广告发出后 24 小时检查一次存活状态
* 存活 → 保底费确认
* 被删 → 保底费冻结，人工复核
* 不做"每小时心跳"，只做"24 小时一次检查"

**d) 争议处理（最小版）**

* 频道主和广告主都可以通过 bot 发起争议
* 平台管理员在 Web 后台看到争议列表
* 查看 message\_id 状态 + 点击日志 + 快照
* 48 小时内人工裁决
* 不做自动仲裁，不做复杂证据链（Phase 3 再做）

### 4.4 Phase 2 的生死线

|指标|及格线|说明|
|-|-|-|
|频道主数量|≥ 50|含各等级|
|广告主数量|≥ 15|含复投客户|
|月交易额|> $10,000|开始有真实营收|
|平台月收入|> $2,000|至少覆盖服务器成本|
|频道主月留存|> 70%|关键指标|
|广告主复投率|> 60%|关键指标|
|争议率|< 8%|双轨模式下应控制住|
|争议处理时长|< 48h|可以人工但要及时|

**Phase 2 的时间框：6 个月。如果 6 个月后月交易额没过 $10,000，需要重新评估市场需求。**

## 第五部分：Phase 3——效果市场（10-18 个月）

Phase 3 是 v3.0 描述的"终局"。只有在 Phase 2 的指标全部达标后才进入。

### 5.1 Phase 3 新增的能力

此时才引入 v3.0 中设计的完整能力集：

* **完整的 CPA 计费模式**（包括转化回传 API）
* **四层风控体系**（此时有足够数据训练阈值）
* **频道信用评分系统**（基于 Phase 1-2 的履约数据）
* **数据驱动的匹配算法**（基于历史 CTR 和转化数据）
* **多币种结算**（USDT + TON + 法币）
* **开放注册**（取消邀约制）
* **自助广告主后台**（Web 版）
* **完整的争议证据链和半自动仲裁**
* **公开 API**

### 5.2 Phase 3 的竞争护城河

到这个阶段，护城河应该已经从以下五个维度形成：

1. **数据壁垒：** 12+ 个月的投放数据，知道什么广告在什么频道转化最好
2. **供给壁垒：** 50+ 个活跃频道已经形成使用习惯
3. **工具锁定：** 频道主日常使用频道诊断、内容排期等工具
4. **结算信任：** 按时结算的记录是最硬的信任资产
5. **归因能力：** 302 网关 + deep link + 转化回传形成完整归因基础设施

## 第六部分：计费模型的阶段性演进（取代 v3.0 的一次性设计）

|阶段|计费模式|理由|
|-|-|-|
|**Phase 0**|无计费（自用）|验证工具可用性|
|**Phase 1**|固定单价/条|最简单、零争议、频道主确定性最高|
|**Phase 2**|保底 + CPC 双轨|开始引入效果信号，但保底保护频道主|
|**Phase 3**|CPC / CPA / Hybrid 自选|市场成熟后按 v3.0 设计开放全部模式|

**核心原则：计费复杂度必须匹配交易量。交易量低的时候用简单模式，交易量高了再上复杂模式。**

## 第七部分：冷启动的具体执行策略（取代 v3.0 的泛泛而谈）

### 7.1 "带着需求来找供给"策略

不要先招频道主再找广告主。反过来。

**步骤：**

1. 先找 3-5 个你认识的广告主（或你自己就是广告主），确认他们有明确的投放需求和预算
2. 拿着"我已经有 $X 预算要投放"去找频道主，告诉他们"你接入就有广告发，不用等"
3. 频道主的动力从"也许以后能赚钱"变成"接入就有钱赚"

### 7.2 "超级节点"策略

不要广撒网招 100 个小频道。先找 3-5 个"超级节点"——有影响力、有多个频道、在频道主圈子里有话语权的人。

**为什么：**

* 一个管理 10 个频道的频道主，等于一次接入 10 个供给单位
* 他如果在圈子里说"这个平台靠谱"，胜过你发 100 条推广
* 给超级节点特殊待遇：更高的分成比例、优先结算、专属客服

### 7.3 "自己就是供给"策略

如果你自己有频道（原始需求中提到了），那你自己就是供给端的种子。

**具体做法：**

* 你自己的频道先接入，证明工具好用
* 邀请你频道里的读者中有频道的人接入
* 用你自己频道的广告收入数据作为案例展示给其他频道主

## 第八部分：应对致命弱点七（Telegram API 依赖）的 Plan B

### 8.1 短期应对

* 将所有 Telegram API 调用封装在一个抽象层后面，不在业务逻辑中直接调用 API
* 监控 Telegram 的 Terms of Service 变更和 API 更新日志
* 保持与 Telegram 官方平台的"互补"关系而非"竞争"关系

### 8.2 中期应对

* 将频道诊断、内容排期等工具能力设计为"平台无关"的——即使 Telegram 政策变化，这些工具仍然有价值
* 积累广告主和频道主的关系资产——即使平台形态改变，这些关系可以迁移

### 8.3 长期应对

* Phase 3 之后考虑扩展到其他平台（Discord、WhatsApp Channel 等）的广告撮合
* 将核心能力定义为"归因 + 结算 + 风控"，而非"Telegram 广告 bot"

## 第十部分：平台公开承诺（简化版）

v3.0 列了 8 条承诺。Phase 1 只需要 4 条：

1. **广告经过审核**，不接明显诈骗和非法内容
2. **频道主有控制权**，可以设置类目黑名单和每日上限
3. **钱的去向透明**，广告主能看到投到了哪些频道，频道主能看到每条广告的收入
4. **按时结算**，承诺的结算周期必须兑现

其余承诺（争议有流程、不暗扣、风控有证据链等）在 Phase 2 逐步添加。

## 第十二部分：v4.0 的一句话总结

### v3.0 说的是：

> "可信点进去，可信转起来，可信结得清，可信活得久"

### v4.0 在此基础上加一句：

> \*\*"先活着，再可信。"\*\*

v4.0 的核心改变不是否定 v3.0 的终局设计，而是承认一个现实：**完美的系统设计如果不能在 6 个月内产生真实收入，它就只是一份好看的文档。**

v4.0 的时间表：

|里程碑|时间|判定标准|
|-|-|-|
|Phase 0 上线|第 6 周|自己用着比手动发广告好用|
|Phase 1 生死线|第 4 个月|20 个外部频道、5 个外部广告主、$1,000 月交易|
|Phase 2 生死线|第 10 个月|50 个频道、15 个广告主、$10,000 月交易|
|Phase 3 启动|第 12 个月|Phase 2 全部指标达标|

**每个阶段都有明确的"不达标就停下来反思"的机制。这才是创业项目真正需要的蓝图。**
