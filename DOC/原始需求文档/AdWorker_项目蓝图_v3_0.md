## 第一部分：项目本质与战略定位

### 1.1 AdWorker 是什么

AdWorker 是面向 Telegram 生态的**广告撮合与效果履约平台**。

它不是广告代发机器人，不是展示量交易市场，不是 Telegram 万能后台。它是一个双边交易系统，左端连接广告主的预算和转化需求，右端连接频道主的内容资产和变现需求，中间由平台提供审核、匹配、投放、归因、结算、风控六项核心能力。

### 1.2 与 Telegram 官方广告平台的关系

Telegram 官方广告平台（Sponsored Messages）在 2025-2026 年间持续演进，已支持频道订阅量 1,000 以上的公开频道投放，并引入 50% 创作者分成。但官方平台存在明确的结构性限制：广告内容限 160 字符纯文本，仅支持站内链接跳转，不支持多媒体素材，且最低投放门槛较高。

AdWorker 不复制官方能力，而是填补官方未覆盖的缺口：

- 支持多媒体广告素材（图文、视频、按钮组合）
- 支持站外链接跳转与深度归因
- 服务中小型广告主，降低投放门槛
- 为中文 Telegram 生态提供更贴合的匹配与结算体系
- 提供比私聊谈单更标准化、更透明的交易流程

### 1.3 v3.0 的核心定位语

> AdWorker 是一个放弃以展示量为主结算逻辑、以 CPC/CPA 为核心计费、以可验证动作为中心、以硬账本和观察期为约束的 Telegram 效果广告撮合与履约平台。

这个定位同时满足三件事：保护广告主的预算不被虚假流量消耗，不给频道主制造不可承受的收入不确定性，让平台通过归因能力和风控能力建立真正的竞争壁垒。

## 第二部分：四方价值模型

AdWorker 的参与方不是三角，而是四方。

### 2.1 广告主（Advertiser）

**核心需求：** 可控投放、可信效果、可解释账单。

**平台承诺：** 你花的钱，要么换来可验证点击，要么换来可核验转化动作。预算去向透明，渠道表现可比，素材效果可测。

### 2.2 频道主（Publisher）

**核心需求：** 低打扰变现、透明收益、充分控制权、稳定结算。

**平台承诺：** 你不靠刷阅读赚钱，靠真实用户响应赚钱。你对广告类目、频率、时间、格式拥有完全控制权。平台保障账本透明，收益可核对。

### 2.3 平台运营方（Operator）

**核心需求：** 撮合效率、数据壁垒、可持续收入。

**平台承诺：** 平台不靠信息差赚钱，靠归因能力、风控能力和账务能力赚钱。平台收入来源清晰，不暗扣、不超频、不纵容灰产。

### 2.4 最终用户（Audience）

**核心需求：** 低侵扰、内容相关性、不被垃圾广告污染频道体验。

**平台承诺：** 广告密度受控，广告内容经审核，频道主有权拒绝不适配广告。用户体验是平台长期存活的根基——用户反感导致频道流失，频道流失导致供给枯竭。

## 第三部分：交易模型

### 3.1 四层交易对象

**第一层：广告活动 Campaign**
定义总目标、预算上限、结算方式、期望动作类型、投放周期。

**第二层：广告素材 Creative**
定义文案、按钮、媒体附件、目标链接、跳转方式（站内 / 站外）、A/B 版本标记。

**第三层：投放批次 Placement Batch**
定义本次投放的频道组合、每频道预估库存、预冻结预算、排期窗口。

**第四层：结果事件 Outcome Event（v3.0 新增）**
定义计费动作事件，是效果结算的关键对象。

### 3.2 Outcome Event 类型

| 事件类型 | 说明 | 适用计费 |
|---------|------|---------|
| `click_valid` | 通过平台网关的有效点击 | CPC |
| `bot_start` | 用户通过 deep link 启动目标 bot | CPC / CPA |
| `join_channel` | 用户订阅目标频道 | CPA |
| `join_group` | 用户加入目标群组 | CPA |
| `lead_submit` | 用户提交表单或联系方式 | CPA |
| `register_success` | 广告主回传注册成功信号 | CPA |
| `payment_success` | 广告主回传支付成功信号 | CPA |
| `custom_event` | 广告主自定义回传事件 | CPA |

## 第四部分：计费模型

### 4.1 四种计费模式

**模式一：CPC（按有效点击）**

适用场景：外链点击、bot 启动点击、频道跳转点击。
结算依据：用户通过平台短链或 bot 中继产生有效点击，经过去重和风控过滤后计费。

**模式二：CPA（按可验证动作）**

适用场景：注册、加群、订阅、表单提交、支付成功。
结算依据：广告主或目标 bot 回传明确动作事件，经平台核验后计费。

**模式三：Hybrid CPC+CPA（混合模式）**

适用场景：既看点击也看后续动作的广告主。
结算逻辑：先按点击给基础费用，再按转化动作补差价。兼顾频道主的基础收入和广告主的效果追求。

**模式四：保底履约 + 效果加成（Guarded Hybrid）**

适用场景：品牌曝光类广告、频道主不愿纯效果接单的早期阶段。
结算逻辑：平台给频道极低的基础履约费（广告成功发布且存活超过 N 小时即产生），主要收益仍来自 CPC/CPA 浮动部分。

### 4.2 默认推荐与禁止

- 平台默认推荐顺序：CPA > CPC > Hybrid > 保底履约
- 平台不推荐：纯 CPM 结算（阅读量仅作为风控参考信号，不作为主结算口径）
- 平台禁止：无归因的纯展示买卖

### 4.3 频道主的三种接单模式

| 模式 | 说明 | 适合谁 |
|------|------|--------|
| **Auto CPC/CPA** | 平台自动接单，频道主接受效果型广告，收益高但波动大 | 中小频道，追求最大化收入 |
| **Guarded Hybrid**（默认） | 有极低履约底费 + CPC/CPA 奖励，收入有底线 | 大多数频道主 |
| **Manual Approval** | 频道主手工确认每条广告后才投放 | 高质量频道，强调调性控制 |

## 第五部分：归因体系

v3.0 的技术核心不是发消息，是归因。

### 5.1 站内归因链路（Telegram 内目标）

适用：bot、频道、群组等 Telegram 站内目标。

标准流程：

1. 广告按钮注入唯一追踪参数（如 `t.me/AdWorkerBot?start=ext_aff_{campaign}_{creative}_{placement}`）
2. 用户点击后先进入平台中继 bot
3. 平台记录 `user_id`、来源频道、素材版本、时间戳
4. 中继 bot 通过 `answerCallbackQuery` 瞬间重定向到最终目标
5. 目标方回传后续动作（如 bot start、注册、支付）
6. 平台生成 outcome event，进入结算流程

Telegram 的 deep linking 机制原生支持 start 参数传递（最长 64 字符），平台通过编码将 campaign_id、creative_id、placement_id 压缩注入参数，实现端到端归因。

### 5.2 站外归因链路（外部网页目标）

适用：网页、电商、外部落地页。

标准流程：

1. 所有外部链接强制转换为平台短链（`https://go.adworker.io/r?id=xxx`）
2. 短链命中 302 重定向网关
3. 网关记录 `click_id`、UA、IP、referer-like context、时间戳
4. 即时跳转到落地页（确保移动端无感知延迟）
5. 广告主可选回传 register / pay / submit 事件

### 5.3 有效点击判定规则

不是点了就算钱。一个 `click_valid` 至少满足：

- 非黑名单 UA（过滤已知爬虫和自动化工具）
- 非数据中心 IP（过滤 AWS、DigitalOcean 等托管服务器来源）
- 非秒退异常批量请求
- 同用户 / 同设备 / 同 IP 在冷却期内不重复计费
- 命中目标跳转成功
- 通过基础风控阈值

**刚性原则：平台记录点击 ≠ 平台承认该点击可结算。**

## 第六部分：风控体系

### 6.1 四层风控架构

**第一层：阅读风控（辅助信号）**

阅读量不用于主结算，仅作为频道评级和异常检测的参考维度。监控指标包括：异常阅读曲线（发布后几分钟内产生 90% 视图然后归零）、零点击高阅读、异常时段峰值。

**第二层：点击风控**

| 检测维度 | 具体指标 |
|---------|---------|
| IP/ASN 聚类 | 大量来自同一数据中心 IP 段的点击 |
| UA 异常 | 已知爬虫特征、无浏览器指纹 |
| 频率异常 | 短时间高频点击 |
| 行为断裂 | 点击后无任何后续行为（零停留） |
| CTR 异常 | 同素材在单频道 CTR 偏离同类频道均值 3 个标准差以上 |

**第三层：转化风控**

| 检测维度 | 具体指标 |
|---------|---------|
| 活跃度断裂 | bot start 后无任何后续活跃 |
| 批量异常 | 回传注册事件在短时间内大量聚集 |
| 设备重复 | 同设备指纹反复注册 |
| 回传可信度 | 支付回传金额异常或时间戳不合理 |

**第四层：履约风控**

| 检测维度 | 具体指标 |
|---------|---------|
| 广告存活 | 广告是否在观察期内被删除 |
| 权限完整 | 机器人是否仍具备 `can_post_messages` 权限 |
| message_id 有效性 | 通过 `getMessages` 检查消息是否仍然存在 |
| 频道合规 | 频道是否接入竞品平台或发布违规内容 |

### 6.2 风控刚性原则

- 每次投放前自动检查机器人权限状态（权限快照）
- 机器人被踢或失权立即熔断该频道的所有待执行任务
- 广告被删自动进入"待裁决"状态，频道主无合理理由则扣除收益并惩罚信用分
- 所有风控判定记录不可篡改，作为争议处理的证据链

## 第七部分：账务与结算体系

### 7.1 广告主资金流

```
充值 → 创建 Placement Batch → 预冻结预算 → 
点击/动作发生后逐条微结算 → 无效点击不扣费 → 
未履约渠道自动解冻 → 争议订单先冻结再裁决
```

账户字段：

| 字段 | 说明 |
|------|------|
| `available_balance` | 可用余额 |
| `reserved_balance` | 冻结余额（投放中锁定） |
| `spent_balance` | 已消耗 |
| `refunded_balance` | 已退款 |
| `disputed_balance` | 争议中冻结 |

### 7.2 频道主收益流

```
广告成功发出 → pending_earnings → 
观察期（N 小时）→ 存活核验通过 → confirmed_earnings → 
结算周期到达 → settled_earnings → 提现
```

观察期内系统定时执行"存活心跳检查"：通过 `getMessages` 接口验证 `message_id` 是否仍有效。若发现广告已被删除，自动取消该笔收益并触发风控流程。

### 7.3 平台收入来源

- 点击/动作抽佣（主要收入）
- 技术服务费（归因、报表、API 调用）
- 高级风控服务费（定制反作弊策略）
- 代运营服务费（大客户专属）
- 自有广告位（平台在合作频道中的少量自用广告位）

### 7.4 多币种结算（v3.0 新增）

考虑到 Telegram 生态中 TON 币和 Telegram Stars 的广泛使用：

- 广告主充值支持：USDT、TON、法币（银行卡/电汇）
- 频道主提现支持：USDT、TON、法币
- 平台内部账本统一以 USDT 计价，汇率锁定在充值/提现时点
- 未来可考虑支持 Telegram Stars 作为小额交易介质

## 第八部分：频道侧机制

### 8.1 频道接入流程

1. 频道主私聊 AdWorker bot，选择"接入频道赚钱"
2. 将 bot 拉入目标频道并授予 `can_post_messages` 权限
3. 平台自动验证权限状态
4. 频道主填写基础资料（语言、类目、地区）
5. 平台人工审核（初期邀约制）
6. 审核通过后配置广告偏好
7. 进入"可接单"状态

### 8.2 频道主控制项（刚性保留）

| 控制维度 | 说明 |
|---------|------|
| 类目黑名单 | 拒绝特定行业广告 |
| 时间窗 | 广告允许发布的时段 |
| 每日上限 | 每天最多几条广告 |
| 竞品冷却期 | 同类广告最小间隔时间 |
| 内容限制 | 是否接受外链 / bot 引流 / 图片 / 视频 |
| 最小收益门槛 | 低于此金额的广告不接 |
| 确认模式 | 自动 / 半自动 / 人工确认 |
| 敏感词黑名单 | 包含特定关键词的广告自动拒绝 |
| 节假日暂停 | 特殊时段暂停投放 |
| 广告间距 | 两条广告之间的最小间隔 |

### 8.3 频道分级

| 等级 | 核心指标 | 权益 |
|------|---------|------|
| **S 级** | 订阅量 > 100k，日活阅读 > 40%，履约率 100% | 优先推荐，溢价定价 |
| **A 级** | 订阅量 20k-100k，阅读稳定，争议率 < 1% | 自动调度主力 |
| **B 级** | 订阅量 5k-20k，垂直领域活跃 | 性价比选择 |
| **C 级** | 新接入或长期未更新 | 观察期，限制接单频率 |
| **R 级** | 存在刷量、恶意秒删等行为 | 冻结收益，永久拉黑 |

评级依据综合以下维度（不只看订阅量）：更新频率、阅读稳定性、历史履约率、广告后删除率、争议率、用户响应质量（CTR、转化率）、风险记录。

### 8.4 频道主冷启动激励（v3.0 新增）

为解决"没有广告→频道主不愿接入"的冷启动困境：

- 新接入频道前 30 天享受"保底收益保障"：即使广告点击量低，也给予最低基础收益
- 前 10 条广告免抽佣，全部收益归频道主
- 提供"频道诊断报告"作为增值服务（分析阅读曲线、最佳发布时段、受众画像）
- 邀请制下优先接入有明确自有广告需求的频道，确保广告供给

## 第九部分：广告主侧产品定义

### 9.1 广告主后台（效果后台，非排期后台）

广告主在 v3.0 里看到的核心数据面板：

| 维度 | 指标 |
|------|------|
| **预算** | 总预算 / 已冻结 / 已消耗 / 可用余额 |
| **效果** | 有效点击数 / 有效动作数 / CPC / CPA 实际成本 |
| **渠道** | 频道分布 / 渠道质量分 / 各频道 CTR 和转化率 |
| **素材** | 各素材版本表现对比（A/B 测试） |
| **风控** | 无效流量拦截率 / 争议率 |
| **时间** | 消耗进度曲线 / 时段分布 |

### 9.2 广告主双轨服务模型（v3.0 新增）

**自助轨道：** 广告主通过 bot 或 Web 后台自行创建活动、提交素材、设定预算。适合有投放经验的广告主。

**代运营轨道：** 平台运营团队协助广告主完成素材优化、频道选择、预算分配、效果复盘。适合大客户或初次投放的广告主。前期以代运营为主，后期随平台成熟逐步引导自助化。

### 9.3 广告类型（MVP 支持 4 种）

1. **频道引流广告** — 目标：引导用户订阅某 Telegram 频道
2. **群组引流广告** — 目标：引导用户加入群组
3. **Bot 启动广告** — 目标：用户点击按钮触发 bot deep link / start 参数
4. **外链跳转广告** — 目标：访问外部页面（必须走平台 302 网关）

暂不支持：表单广告、多步漏斗广告、Mini App 内嵌广告（留待 Phase 3）。

## 第十部分：审核体系

### 10.1 行业分类红线

**白名单：**
正常频道推广、正常 bot 推广、正常产品宣传、正常活动宣传、教育培训、软件产品、电商。

**灰名单（需高级人工审核）：**
金融衍生品、医疗保健、博彩边缘类、成人擦边类、高承诺收益类。

**黑名单（永久禁止）：**
明显诈骗、非法博彩、假冒平台、非法商品/服务、虚假承诺拉人头项目、恶意跳转/钓鱼、恶意木马分发。

### 10.2 审核维度

- 行业合法性
- 是否诈骗/误导风格
- 文案质量（拒绝极低质量内容）
- 落地链接安全性检查
- 是否适合目标频道受众
- 是否存在重复轰炸
- 是否违反 Telegram 平台条款

### 10.3 合规刚性约束（v3.0 新增）

- Telegram 平台条款明确禁止 spam、scam 和大多数国家认定的非法活动，AdWorker 的审核标准必须至少不低于这个底线
- 2024 年 Durov 被捕后 Telegram 加强了合规执行力度，平台必须建立完整的内容审计日志以应对可能的监管审查
- 所有广告素材和频道配置在投放时自动快照存档，作为合规证据

## 第十一部分：匹配与调度

### 11.1 规则引擎（Phase 1-2）

匹配条件（布尔逻辑初筛）：

```
广告类目 ∩ 频道接受类目 ≠ ∅
AND 广告语言 = 频道语言
AND 预算 ≥ 频道最低可投阈值
AND 频道当日库存未满
AND 频道时间窗允许
AND 同类广告冷却期满足
AND 频道风险评分 ≤ 阈值
AND 广告主风险评分 ≤ 阈值
```

### 11.2 库存管理

频道库存是稀缺资源，必须刚性管理：

- 每频道每日广告最大条数（频道主设定 + 平台上限）
- 连续两条广告最小间隔
- 广告占频道总内容比例上限（建议 ≤ 20%）
- 特殊节日/活动期间例外规则

### 11.3 动态优先级分发（Phase 3）

当多个广告竞争同一频道库存时，调度引擎根据加权公式决定优先级：

```
Priority = w₁ × CTR_history + w₂ × Publisher_credit + w₃ × Bid_amount + w₄ × Creative_freshness
```

其中 CTR_history 为该素材在类似频道中的历史点击率，Publisher_credit 为频道主的履约信用分。此机制自发淘汰低转化素材，奖励高响应频道。

### 11.4 FloodWait 防御机制

Telegram Bot API 对消息发送有严格频率限制（单频道约 1 条/秒，不同对话框约 30 条/秒）。AdWorker 必须采用分布式任务队列架构：

- 中心消息分发器为每个频道建立独立的发送窗口
- 实时捕获 `retry_after` 参数，使用指数退避算法自动调整重试频率
- 目标投递成功率 ≥ 99.9%

## 第十二部分：争议处理

### 12.1 三大争议类型

**履约争议：** 发没发出去、发出去后删没删、权限是否有效。

**点击争议：** 是不是有效点击、有没有重复计费、有没有可疑流量。

**转化争议：** 转化是否真实、回传是否可信、是否被广告主恶意拒付。

### 12.2 证据链（刚性要求）

每笔争议处理必须基于以下证据，缺一不可：

- 广告素材快照（投放时点的完整内容）
- 频道配置快照（投放时点的频道偏好设置）
- Bot 权限快照（投放前的权限检查记录）
- `message_id` 与发送时间戳
- 删除监控日志（何时被删除、由谁触发）
- 短链点击日志（IP、UA、时间、去重结果）
- IP/ASN 风控结论
- 转化回传日志（如适用）

### 12.3 处理原则

1. 先看履约事实
2. 再看配置与规则
3. 再看平台日志与风控结论
4. 最后才是人工裁定

所有人工裁定必须附带处理备注，记录进审计日志。

## 第十五部分：MVP v3.0 范围

### 15.1 MVP 只做 7 件事

1. **邀约制频道接入** — 只接自有频道和少量可信外部频道
2. **CPC 优先** — 先把可验证点击跑稳，暂不做复杂 CPA 市场
3. **302 网关短链** — 所有外链统一中转，记录点击数据
4. **Bot Deep-Link 归因** — 至少支持 start 参数归因
5. **硬账本** — 预冻结、逐条扣费、观察期结算必须上线
6. **争议证据链** — 快照、message_id、点击日志、删除日志必须齐备
7. **基础风控** — IP/UA 去重、秒删检测、异常频率拦截

### 15.2 MVP 不做

- 完全开放注册
- 实时竞价
- 多层分销
- 复杂推荐算法
- 跨平台广告 API
- 纯品牌广告产品化
- Mini App 广告
- 多币种自动结算（先只支持 USDT）

## 第十六部分：三阶段路线图

### Phase 1：自用效果闭环（0-3 个月）

**目标：** 跑通「广告创建 → 自动发布 → 网关点击 → bot start / 基础动作归因 → 微结算 → 观察期确认」全流程。

**验收标准：**
- 系统在高并发下的 429 错误处理成功率 > 99%
- 财务账本单笔对账一致性 100%
- 广告能创建、审核、发布、记账、出基础效果报表
- 频道能绑定、配置、接单、看收益
- 平台能人工处理异常和争议

### Phase 2：受邀联盟（3-9 个月）

**目标：** 引入 50-100 个可信频道主，验证三件事：频道主是否接受 Hybrid 模式、广告主是否接受 CPC/CPA 账单、平台能否有效处理点击作弊与秒删争议。

**新增重点：**
- 频道评级体系正式上线
- Hybrid CPC+CPA 计费模式
- 半自动风控规则
- 周期性结算（每周）
- 更完整的效果报表和渠道对比
- 频道主冷启动激励计划

**关键指标：** 频道留存率 > 80%、广告主复投率 > 60%、平均争议处理时长 < 48 小时。

### Phase 3：开放效果市场（9-18 个月）

**目标：** 形成一个默认按 CPC/CPA 交易、按频道信用和素材历史 CTR 自动分发的交易市场。

**新增重点：**
- 自助注册与准入规则
- 数据驱动的匹配算法（替代纯规则引擎）
- CPA 回传 API 开放
- 多币种结算（USDT + TON + 法币）
- Mini App 广告支持探索
- 公开产品文档和 API
- 品牌与客服体系

## 第十七部分：护城河设计

### 17.1 五层护城河

**第一层：高质量频道供给**
掌握一批高质量频道，且这些频道在平台上赚得更稳、被打扰更少、控制权更强。

**第二层：数据壁垒**
积累"什么广告适合什么频道、什么素材会转化、什么时间投效果更好"的数据资产。后来者需要大量时间和交易量才能追赶。

**第三层：结算与信任壁垒**
广告主相信平台不乱扣费，频道主相信平台不乱压佣金。信任建立慢但一旦形成极有价值。

**第四层：工作流壁垒**
频道主已将广告接入、偏好配置、收益查看、结算提现跑在平台上，迁移成本自然上升。

**第五层：归因能力壁垒（v3.0 强调）**
平台的 302 网关、bot 中继、deep link 归因、click dedup、转化回传形成一套完整的归因基础设施。这套能力不是一朝一夕建成的，是平台最深的技术护城河。

### 17.2 关于排他策略的务实建议

前期不建议靠强制排他做护城河。早期平台没有绝对优势时，过强的排他规则会直接降低接入率。真正的护城河应该是收益更稳、体验更好、广告更干净、结算更透明。排他策略可在 Phase 3 平台形成规模优势后再考虑引入。

## 第十八部分：风险清单与应对

| 风险 | 概率 | 严重度 | 应对策略 |
|------|------|--------|---------|
| 频道主刷量骗取收益 | 高 | 极高 | CPC/CPA 计费本身大幅降低刷量收益；多维风控检测 |
| 优质频道流失 | 高 | 高 | Guarded Hybrid 模式保底收入；强控制权设计 |
| 广告主 ROI 不满意 | 高 | 极高 | 透明效果报表；只为有效动作收费；争议可退款 |
| 冷启动双边死锁 | 中高 | 高 | 先自用闭环；频道主冷启动激励；代运营降低广告主门槛 |
| Telegram 官方替代 | 100% | 中 | 不与官方正面竞争；填补官方未覆盖区域 |
| Telegram 政策变化 | 中 | 中 | 持续跟踪 Telegram ToS 变更；保持合规审计日志 |
| 点击欺诈技术升级 | 中 | 高 | 持续迭代风控模型；引入行为分析和设备指纹 |
| 账务纠纷导致信任崩溃 | 低 | 极高 | 硬账本、快照存档、争议流程必须从第一天做对 |

## 第十九部分：平台公开承诺

作为建立信任的基础，平台应从第一天就明确以下公开原则：

1. 不接明显诈骗和非法广告
2. 广告密度受控，不允许无限刷屏
3. 频道主对类目、频率、时间拥有最终控制权
4. 广告主的预算、消耗、渠道分布透明可查
5. 频道主收益可核对，结算规则公开
6. 争议有流程，不靠口头扯皮
7. 平台有服务费规则，不暗扣
8. 风控判定有证据链，可申诉

## 总结：v3.0 的一句话

> v1.0 的核心是"可信发出去"；v2.0 的核心是"可信点进去"；v3.0 的核心是"可信点进去，可信转起来，可信结得清，可信活得久"。

最后一个"活得久"是 v3.0 相对 v2.0 的关键补充：一个效果广告平台如果只关注单次交易的归因闭环而忽略了生态健康（频道主冷启动、广告主入门门槛、合规红线、数据资产积累），最终也会在规模化阶段崩溃。

AdWorker v3.0 的目标不是做一个完美的系统设计，而是做一个"大框架稳、核心账本硬、控制权强、可调参数留成配置层"的可执行平台。
