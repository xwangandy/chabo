AdWorker 项目蓝图 v2.0
主题：以 CPC / CPA 为核心的 Telegram 广告撮合与履约平台

一、项目重新定义

AdWorker v2.0 不是“广告代发机器人”，也不是“刷展示的广告网盟”。

它是一个面向 Telegram 生态的效果分发平台，核心售卖对象不是展示量，而是“可验证点击与可验证动作”。平台通过 bot 中继、深链参数、302 重定向网关、消息存活核验、账本冻结与观察期结算，把广告交易从“口头谈单 + 模糊曝光”升级为“可追踪、可核验、可结算”的履约系统。

二、v2.0 的核心战略变化

v1.0 的核心是“可信分发平台”。

v2.0 要进一步收紧成：

可信效果分发平台。

具体变化有 5 条。

不再把原生阅读量作为主结算依据
阅读量只作为风控参考和频道评级参考，不作为平台主账务口径。因为研究材料已经指出 Telegram 生态存在刷阅读、印象僵尸、异常曲线等问题，阅读量最多只能做辅助信号。
计费中心从 CPM 转向 CPC / CPA
平台默认按点击或动作结算，动作包括：
bot start
加入群/频道
表单提交
注册成功
支付成功
其他广告主回传事件
研究材料已经明确提出，平台应依靠 Deep Linking、bot 中继和后续回传做端到端 CPA 结算。
所有外链必须走平台网关
传统 URL 按钮会绕过 bot 逻辑，导致点击无法归因，因此 v2.0 强制平台将所有外链转换为 302 重定向网关链接。
Bot / deep-link 目标优先于纯外链目标
因为 Telegram 站内链路更容易做归因、更容易反作弊、更容易跑通闭环，所以 v2.0 初期优先支持：
bot 拉起
频道订阅
群组加入
带 start 参数的 bot 转化
外链型广告支持，但不作为最优先场景。
频道收益改为“双层结构”
不是纯点击不给展示钱，也不是纯展示躺赚，而是：
极低履约底费 + CPC/CPA 浮动收益
这样既保证频道主愿意接入，也保证广告主的钱主要花在结果上。

三、平台价值主张

对广告主：
不买模糊曝光，买可验证动作。
你花的钱，要么换来点击，要么换来可核验转化。

对频道主：
不靠刷阅读赚钱，靠真实用户响应赚钱。
平台保障账本透明，给你控制权，也给你更高质量广告。

对平台：
平台不是靠信息差赚钱，而是靠“归因能力 + 风控能力 + 账务能力”赚钱。

四、v2.0 的标准交易模型

v2.0 采用三层交易对象不变，但计费模型改变。

第一层：Campaign
定义总目标、预算、结算方式、期望动作。

第二层：Creative
定义文案、按钮、媒体、目标链接、跳转方式。

第三层：Placement Batch
定义本次投放给哪些频道、每个频道预计库存、预冻结预算。

新增第四层：Outcome Event
定义计费动作事件，是 v2.0 的关键对象。

Outcome Event 典型类型：
click_valid
bot_start
join_channel
join_group
lead_submit
register_success
payment_success

也就是说，v2.0 的钱不是跟着“发出去了多少次”走，而是跟着“发出去以后发生了什么动作”走。

五、计费模型

这是 v2.0 最重要的一部分。

我建议不要写成“全面废除 CPM”，而是正式定义为四种计费模式：

CPC
适用：
外链点击
bot 启动点击
跳转点击

结算依据：
用户通过平台短链或 bot 中继产生有效点击。

CPA
适用：
注册
加群
订阅
表单提交
支付成功

结算依据：
广告主或目标 bot 回传明确动作事件。

Hybrid CPC+CPA
适用：
既看点击，也看后续动作的广告主。
例如先按点击给少量费用，再按注册补差价。
保底履约 + 效果加成
适用：
品牌曝光类、频道不愿纯效果接单的早期阶段。
平台给频道极低的基础履约费，主要收益仍来自 CPC/CPA。

平台默认推荐顺序：
CPA > CPC > Hybrid > 保底履约

平台不推荐：
纯 CPM 结算

六、点击与转化归因体系

v2.0 的技术核心不是发消息，是归因。

A. Telegram 站内归因链路

适用：
bot、频道、群组等 Telegram 站内目标。

标准做法：

广告按钮注入唯一追踪参数
用户点击后先进入平台中继 bot
平台记录 user_id、来源频道、素材版本、时间戳
再跳转到最终 bot/频道/群组
目标方回传后续动作
平台生成 outcome event，进入结算
这套思路和研究材料里“站内全路径追踪技术”一致。

B. Telegram 站外归因链路

适用：
网页、电商、外部落地页。

标准做法：

所有外部链接平台化短链
短链命中 302 网关
网关记录 click_id、UA、IP、referer-like context、时间戳
再跳转到落地页
广告主可选回传 register / pay / submit
这和研究材料里“URL 按钮盲区必须用 302 重定向网关”完全一致。

C. 有效点击判定规则

不是点了就算钱。

一个 click_valid 至少满足：
非黑名单 UA
非明显爬虫
非秒退异常批量请求
同用户 / 同设备 / 同 IP 在冷却期内不重复计费
命中目标跳转成功
通过基础风控阈值

这里要直接写死：
平台记录点击，不等于平台承认该点击可结算。

七、风控体系 v2.0

v2.0 的风控不再以“防秒删”为主，而是升级成“防假动作”。

核心风控面分四层：

阅读风控
只作为辅助，不用于主结算。
看异常阅读曲线、零点击高阅读、异常时段峰值。
点击风控
看：
IP/ASN 聚类
UA 异常
短时间高频点击
点击后无任何后续行为
同素材在单频道 CTR 异常偏离
转化风控
看：
bot start 后无后续活跃
回传注册批量异常
支付回传不可信
同设备反复注册
履约风控
看：
广告被删
机器人失权
message_id 丢失
频道频繁争议
频道接入竞品或规则冲突

研究材料还强调了权限快照、失权熔断、message_id 存储、配置快照归档，这些都必须进入 v2.0 的刚性设计。

八、账务与结算体系 v2.0

v2.0 必须保留 v1.0 的硬账本逻辑，而且更重要。

A. 广告主资金流

充值
创建 Placement Batch
预冻结预算
点击/动作发生后逐条微结算
无效点击不扣费
未履约渠道自动解冻
争议订单先冻结再裁决

这个和研究材料中的“预冻结与逐条扣费”是一致的。

B. 频道主收益流

广告发出后不立即确认
先进入 pending_earnings
经过观察期，确认未秒删且点击/动作数据可结算
再进入 confirmed_earnings
周期性提现结算
研究材料已经明确提出观察期结算、消息存活核验、confirmed_earnings，这一套应保留。

C. 平台收入流
平台收入不再主要来自展示差价，而来自：
点击/动作抽佣
技术服务费
高级风控费
代运营服务费
大客户定制归因服务

九、频道侧机制 v2.0

频道主能不能接入，不只取决于钱，还取决于风险分配是否合理。

所以 v2.0 给频道主三种接单模式：

Auto CPC/CPA
平台自动接单，频道主接受效果型广告。
收益高，但波动大。
Guarded Hybrid
有极低履约底费 + CPC/CPA 奖励。
适合大多数频道主，应该作为默认模式。
Manual Approval
频道主手工确认广告。
适合高质量频道或强调调性的频道。

频道主必须保留的控制项：
类目黑名单
时间窗
每日广告上限
竞品冷却期
是否接受 bot 引流
是否接受外链
是否接受图片/视频
最小收益门槛
自动 / 半自动 / 人工确认

研究材料也明确要求“控制必须强”，这个在 v2.0 里更不能弱化。

十、广告主侧产品定义 v2.0

广告主在 v2.0 里看到的，不该再是“发了多少条”，而是：

预算
已冻结
已消耗
有效点击
有效动作
CPA / CPC 成本
渠道表现
素材表现
无效流量拦截率
争议率
渠道质量分

也就是说，广告主后台应该从“排期后台”升级成“效果后台”。

十一、系统架构 v2.0

v2.0 的能力域建议是 10 个：

Identity & Accounts
账户、组织、角色、广告主、频道主、bot 实体
Publisher Profiling
频道接入、画像、等级、广告偏好、信用分
Campaign & Creative
广告活动、素材、目标、预算、按钮、落地页
Link Gateway
短链、302 网关、点击记录、UA/IP 解析、去重
Telegram Relay
中继 bot、deep link、callback / start 捕获
Placement & Scheduler
批次排片、库存管理、频道窗口、中心分发器、429 退避
研究材料明确要求中心消息分发器、每频道独立发送窗口、retry_after 与指数退避，这个域必须单独存在。
Delivery & Heartbeat
消息发送、message_id 记录、存活核验、删除监控
Billing & Ledger
预冻结、微结算、收益确认、调账、争议冻结
Fraud & Risk
点击风控、转化风控、频道信用、广告行业审核
Dispute & Evidence
配置快照、权限快照、素材快照、日志证据、仲裁

十三、争议处理 v2.0

争议类型变成三大类：

履约争议
发没发出去、发出去后删没删、权限是否有效。
点击争议
是不是有效点击、有没有重复点击、有没有可疑流量。
转化争议
转化是否真实、回传是否可信、是否被广告主恶意拒付。

证据链必须包含：
广告素材快照
频道配置快照
bot 权限快照
message_id
发送时间
删除监控日志
短链点击日志
IP/UA 风控结论
转化回传日志

研究材料已经把“配置快照存档”提到了很高优先级，这里直接落成正式设计即可。

十四、MVP v2.0 范围

不要一上来做全平台开放版。

MVP 只做 6 件事：

邀约制频道接入
只接自有频道和少量可信外部频道。
CPC 优先
先不做复杂 CPA 市场，先把可验证点击跑稳。
302 网关短链
所有外链统一中转。
Bot Deep-Link 归因
至少支持 start 参数归因。
硬账本
预冻结、逐条扣费、观察期结算必须上线。
争议证据链
快照、message_id、点击日志、删除日志必须齐。

MVP 先不做：
完全开放注册
实时竞价
多层分销
复杂推荐算法
跨平台广告 API
纯品牌广告产品化

十五、三阶段路线图 v2.0

Phase 1：自用效果闭环
目标：
跑通“广告创建 → 自动发布 → 网关点击 → bot start / 基础动作归因 → 微结算 → 观察期确认”。
这和研究材料的“先闭环、再联盟、后平台”仍然一致，只是把闭环重点从基础报表升级到效果归因。

Phase 2：受邀联盟
目标：
引入 50–100 个可信频道主，验证：
频道主是否接受 Hybrid 模式
广告主是否接受 CPC/CPA 账单
平台能否处理点击作弊与秒删争议

Phase 3：开放效果市场
目标：
形成一个默认按 CPC/CPA 交易、按频道信用和素材历史 CTR 自动分发的交易市场。研究材料中也已经提到“规则优先、再到数据驱动”和以历史 CTR、履约信用分做优先级分发，这里可以作为第三阶段的算法基础。

十六、我对你这个“非共识判断”的最终修正

我给你的最终版本不是：

“完全放弃 CPM，全面转向 CPC/CPA。”

而是：

“AdWorker v2.0 放弃以 CPM 作为主结算逻辑，转向以 CPC/CPA 为核心、以可验证动作为中心、以硬账本和观察期为约束的混合效果平台。”

这句话更对，也更能活。

因为它同时满足三件事：

保护广告主的钱
不给频道主制造不可承受的不确定性
让平台有真正的风控与信用壁垒

最后给你一句最关键的话：

v1.0 的平台核心是“可信发出去”；
v2.0 的平台核心必须是“可信点进去，可信转起来，可信结得清”。
