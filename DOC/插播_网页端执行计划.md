# 插播网页端执行计划

版本：v0.5
日期：2026-05-02
状态：执行中

## 1. 执行原则

本项目按“复杂交互最优”推进，不按“最省事后台”推进。框架已经定版：

```text
React + TypeScript + Vite
React Router
TanStack Query
Ant Design
AG Grid Enterprise
FastAPI JSON API
```

执行期间默认自主推进，不逐项等待确认。只有以下情况需要暂停说明：

- 需要真实 Telegram Bot token、域名、服务器、支付或公司 SSO 凭证。
- 需要决定商业授权，例如 AG Grid Enterprise 是否购买。
- 业务规则存在互相冲突，无法通过保守默认值继续实现。

## 2. 总阶段

### M0：工程骨架

- 新建 `web/` React/Vite 前端工程。
- 新建 `src/chabo/webapi/` FastAPI JSON API。
- 新增 `portal_access`、`web_sessions`、`login_tokens`、`placement_plans` 等基础表。
- 增加 `chabo run-api`。
- 管理端、广告主端、频道主端先有可登录、可路由、可读取指标的页面。

验收：

- `python3 -m unittest discover -s tests` 通过。
- `python3 -m compileall -q src tests` 通过。
- `npm run build` 通过。

### M1：认证与权限闭环

- Telegram Mini App `initData` 校验。
- Bot 一次性 magic link 登录。
- 管理员账号登录。
- portal access 自动开通和手工授予。
- 管理员 impersonation。

验收：

- 无权限访问返回 403。
- 管理员可切换三端门户。
- 广告主/频道主只能访问自己数据。

### M2：管理端 MVP

- 订单列表、订单详情、审核、拒绝。
- 投放列表、失败投放、退款。
- 充值申请审核。
- 争议处理。
- 账户、频道检索。
- 审计日志。

验收：

- 管理员可不用 Bot 完成核心运营动作。
- 所有高影响动作写 audit/tool call log。

### M3：广告主端 MVP

- 广告素材库。
- 频道市场。
- 收藏/频道集合。
- 投放计划草稿。
- AG Grid 投放矩阵。
- 计划校验和提交生成订单。
- 钱包与订单。

验收：

- 广告主可从网页端完成批量投放计划并生成订单。
- 矩阵支持跨页选择、批量编辑和校验结果。

### M4：频道主端 MVP

- 频道列表。
- 频道详情配置。
- 展示形态开关。
- 价格和每日限制。
- 收益与广告记录。

验收：

- 频道主可管理多个频道并查看收益。

### M5：H5 适配

- 广告主 H5 简化下单。
- 频道主 H5 基础管理。
- 管理端 H5 审核和异常处理。

验收：

- 手机端不展示完整复杂矩阵，改用集合、模板和摘要确认。

### M6：上线与稳定性

- Nginx SPA + API 配置。
- systemd 服务样例补齐 `chabo-api`。
- Playwright 冒烟。
- 性能和慢查询检查。
- PostgreSQL 迁移评估。
